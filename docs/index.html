Embed the viewer

A CAD engine that lives inside your app.

TreDeSpace is a simple but capable CAD viewer that drops into your product as a single <iframe>. Your app drives it — selection, labels, measurements, clipping, color rules, model import — through a typed, origin-locked postMessage API. And the viewer returns the favor: it hosts your own tools as sandboxed panels, iframes running inside the viewer that talk back over the same protocol. One embed, both directions, nothing to install.

The architecture

Boxes inside boxes — origins inside origins

Each frame is its own web origin with its own sandbox. Nothing reaches across a boundary except a typed message on a locked bridge.

3dviewer.company.com (host origin) TreDeSpace viewer (isolated origin) Your panels (sandboxed iframes) · · · postMessage — origin-locked, protocol v1

Why an iframe both ways

The same bridge, in two directions

The plugin system is the embedding model. There is no second SDK to learn.

Direction 1 · you host the viewer

Drive the 3D scene from your UI

Your app owns the page. It imports tredespace-client.ts, points it at the viewer iframe, and calls typed methods — select parts, drop labels, run color rules, import a model. Events (a user picking a part) stream back to you.

your app → postMessage → viewer iframe

Direction 2 · the viewer hosts you

Ship a panel that lives in the viewer

Register a URL as an External-app panel and the viewer loads it in a sandboxed iframe (?dialog=1). Your panel drives window.parent with the identical API — so a project picker, a report viewer, or an attributes inspector plugs in without forking the viewer.

your panel → window.parent → viewer

This deployment

Three company panels, one viewer

Every panel is served from company.com and speaks the same protocol — data stays yours, whether it comes from a company API or the viewer's built-in SQLite engine running in the browser.

3dviewer.company.com/select-project

Project selector

Picks the active project, then feeds the viewer only what it needs — pushing new or changed models in as they land, instead of a full reload.

  • →Reads what's loaded — assets.list
  • →Streams new / changed models in — assets.import + assets.load
  • →Hands a SQLite DB to the browser engine — sql.import

reports.company.com

Report viewer

Turns a report into a 3D highlight. Send a large set of fullnames and the viewer selects or color-codes every match in a single call.

  • →Names from your company API, or the built-in SQLite engine — sql.query
  • →Drives selection.set / colorRules.set with thousands of names
  • →Reports back missed names it couldn't resolve

attributes.company.com

Detail data viewer

Follows the user. Subscribes to selection in the main frame and shows attributes for whatever they click — no polling, no glue code.

  • →Listens to tree.select events from the viewer
  • →Fetches attributes from your own API, or the built-in engine — sql.query
  • →Can select or fly back on click — selection.set · nav.flyTo

The security model

Isolation is the default, not a setting

Because every layer is a separate origin behind a sandbox, a plugin can render and message — but it cannot read your session or escape its frame.

  • ✓ Strict origin allowlist Every inbound message is dropped unless it comes from the configured origin — if (e.origin !== targetOrigin) return;
  • ✓ Versioned, typed protocol Each message is tagged protocol v1; the client and viewer refuse mismatches instead of guessing.
  • ⌘ Per-plugin sandbox Third-party panels get allow-scripts only — no same-origin, no storage, no top-navigation. They can't touch your DOM or cookies.
  • ✓ Zero shared memory No shared DOM, no globals. Large model files stream as transferable ArrayBuffer chunks — cross-origin safe, zero copies. 
// Copy api/tredespace-client.ts into your app
// it's dependency-free.
import { TredespaceClient } from './tredespace-client';

const client = new TredespaceClient(iframe, {
  targetOrigin: 'https://tredespace.com',
});

await client.ready();               // { version, api }

const { matched, missed } =
  await client.selectionSet(['/SITE/ZONE-1/PIPE-401']);

// react to what the user does in 3D
client.onTreeSelect((e) => highlightInMyGrid(e.fullnames));
