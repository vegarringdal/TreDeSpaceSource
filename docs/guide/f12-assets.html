App layout · F12

The Assets layout

Press F12 (or pick Assets on the App Layout ribbon) to switch to the asset workspace. It puts every panel that deals with files side by side: the library of models you have imported, the databases, the Import Manager that brings new files in, and the Export panel that writes them out again.

  1. Home ribbon — the same ribbon as in F1. Its Assets group opens the panels on this page one by one. See F1 Home.
  2. Hierarchy — the tree of the models that are loaded now, grouped by store and folder.
  3. Model Assets — your library of imported models. Load, unload, organise and delete them. Described below.
  4. SQL Assets — your SQLite databases, in the same stores as the models. Described below.
  5. 3D view — shows the loaded models.
  6. Console — messages, for example how many files an import produced, how long it took, and any warnings from the converter.
  7. Import Manager — brings GLB, TDP, RVM, STEP and IFC files into the library. Described below.
  8. Export — writes what you see to TDP, GLB or IFC, and saves or loads colour and visibility snapshots. Described below.

Where your models are kept

Everything you import is stored in this browser, on this computer. Nothing is uploaded to a server: the conversion runs in your browser too. That has a few consequences:

  • Your library is still there after you close the tab or restart the computer.
  • Another browser, another browser profile, a private window or another computer has its own, separate library.
  • Clearing the browser's data for this site deletes the library. So does Wipe All on the Home ribbon.
  • To give models to someone else, export them as files (see Share models with a colleague).

Importing, loading, unloading, deleting

  • Import converts a file once and keeps the result in your library (Model Assets). Big files take a while; you only do it once.
  • Load shows a model from the library in the 3D view. This is quick, because the hard work was done at import.
  • Unload takes a model out of the 3D view. It stays in the library, ready to load again.
  • Delete removes a model from the library for good.

By default an import is a temp import: the model is loaded straight away, but it is not kept — it is removed from the browser the next time the app starts. Untick Temp import and pick a store to keep it.

Stores and folders

The library is split into stores, one per project or plant. A store holds both models (Model Assets) and databases (SQL Assets) — the two panels show the same list of stores. main always exists. Inside a store, models sit in folders that you can create, rename and nest. Temp imports have their own TEMP section, which empties itself the next time the app starts.

Ribbon

The Home ribbon

F12 uses the Home ribbon. It is described on the F1 Home page. Its Assets group opens Model (Model Assets), Import (Import Manager) and SQL (SQL Assets) on their own, and Wipe All erases every saved setting and the whole library. Clear in the Canvas group unloads every model at once.

Step by step

Common tasks

Import RVM files and keep them

RVM files come from AVEVA PDMS and E3D plant models. Here, five Huldra disciplines go into a new store.

  1. Create a store for the project, if you don't have one yet: see Organise the library. Here it is called Huldra.
  2. In the Import Manager, open Import RVM and press Select RVM file(s)…. Pick one or more .rvm files (hold Ctrl to pick several).
  3. Untick Temp import, and choose the store under Store. Leave the other options as they are for a first try. With several files, each file gets its own folder, named after the file.
  4. Press Import. A progress window shows each phase: converting the file, storing the result, and loading it.
  5. When it is done the models are loaded (because Load after import was ticked) and the camera frames them. They are now in the library, in the chosen store.

Importing the same file again replaces the model with the same store, folder and name. The old copy is removed only after the new one is in place, so a failed import keeps the previous version.

Have a quick look at a file without keeping it

  1. In the Import Manager, open the section for the file type and pick the file.
  2. Leave Temp import ticked (it is ticked every time the app starts) and press Import. No store is needed.
  3. The model loads and appears under TEMP in Model Assets and in the Hierarchy. The next time you start the app, it is gone.

Load and unload models

  1. In Model Assets, select the models: click one, Ctrl + click to add more, Shift + click for a range. Clicking a folder or a store selects everything in it.
  2. Press Load. The camera frames what you just loaded. Tick Keep camera first if you want the view to stay where it is.
  3. To take models out of the 3D view, select them and press Unload. They stay in the library. Clear on the Home ribbon unloads everything.

A model that is already loaded is skipped, not loaded twice. Model Assets does not mark which models are loaded — look in the Hierarchy for that.

Organise the library

  1. To start a new project, open Store Config at the top of Model Assets (or SQL Assets), type a name and a short description, and press Add store.
  2. To make a folder, right-click a store or a folder in the tree and choose New folder inside…. Right-click empty space in the tree for a folder in main.
  3. Drag models or whole folders onto a folder to move them there. Drop them on empty space in the tree to take them out of their folder. Here the five discipline folders were moved into a new folder Topside.
  4. To rename a model, select just that one and type the new name in the Rename box under the tree. To rename or delete a folder, right-click it. Deleting a folder keeps the models that were in it: they move out of the folder (you are asked first).

Models and folders cannot be moved from one store to another. Renaming or moving only changes the library: a model that is loaded keeps its old name and folder in the 3D view, and Unload then no longer finds it. Unload models before you rename or move them. (To get rid of a stray loaded copy, right-click it in the Hierarchy and choose Remove current file/folder, or press Clear on the Home ribbon.)

Export a selection to another program

The Export panel writes out what is visible in the 3D view. To export only some items, hide the rest first.

  1. Select the items, here the safety model /HA-SAFE.
  2. Press Isolate (ALT+H) to hide everything else. See F4 Selection Color.
  3. In the Export panel, under GLB, press Export merged GLB (per color). The file downloads like any other download. Drop it into PowerPoint, Blender or another glTF viewer.
  4. For a BIM tool, press Export merged IFC under IFC instead.

Share models with a colleague

  1. In Model Assets, select the models and press Export. Choose a folder on your computer (the browser asks for permission). Each model is written as a .tdp file, in sub-folders that follow the folders in the library.
  2. Your colleague imports them with Import TDP → Folder + subfolders…. This is the fastest import there is: the files are already converted.

To share a model as you see it — with your colours and hidden items left out — use Export merged TDP in the Export panel instead.

Add a database

  1. In SQL Assets, choose the store under Import to.
  2. Press Import Database and pick one or more SQLite files. If a file with the same name is already in that store, you are asked whether to replace it.
  3. Query it in the F11 SQL Editor.

Panel

Model Assets

The library: every model you have imported, in one tree with a band per store. Everything starts folded up; the number at the end of a row tells how many models are below it.

  1. Store Config — create and delete stores. See below.
  2. Collapse all — folds every store and folder.
  3. Expand all — unfolds them all.
  4. Delete — removes the selected models from the library, after you confirm. A model that is loaded stays in the 3D view until you unload it (with Clear or the Hierarchy's right-click menu, since it is no longer in the library).
  5. Load — loads the selected models into the 3D view.
  6. Unload — takes the selected models out of the 3D view. The files stay in the library.
  7. Export — writes the selected models as .tdp files into a folder you choose, with the library's folders recreated as real folders.
  8. Select all — selects every model the search lets through, in every store.
  9. Deselect all — clears the selection. Selected shows how many are selected.
  10. Keep camera — don't move the camera when models load. Off, the view frames the models you just loaded. The same setting as in the Import Manager.
  11. Pool — how many models load at the same time. The highest value depends on your computer. Each model being loaded is held in memory in full, so lower it if the browser runs out of memory with very large models.
  12. Search — shows only models whose name, folder or store matches. See below.
  13. * / = — how the search matches: * = the text appears anywhere, = = the whole name must match, with * as a wildcard (ALT 620 switches).
  14. The tree — a band per store, then folders, then models with their size. Click to select, Ctrl + click to add or remove, Shift + click for a range. Clicking a store band or folder selects everything in it; the arrow folds it open. Drag to move, right-click for folders.
  15. Rename — appears when exactly one model is selected.

Delete, Load, Unload and Export only act on selected models that the search shows. Their keyboard shortcuts work on the whole selection, search or not: ALT 605 loads, ALT 621 unloads and ALT 612 deletes — without asking. ALT 613 deletes every model in every store, also without asking.

Imported models get their name from the converter. An RVM file split by site gives one model per site, named after it (_HA-PIPE.tdp for the site /HA-PIPE), in a folder named after the file.

Search

Type part of a name, folder or store. Combine words with & (both must match) and | (either may match), and group with parentheses: pipe | safe shows the piping and the safety models. Upper and lower case don't matter. Stores without a match are hidden while you search.

Store Config

The same section is at the top of both Model Assets and SQL Assets; a change in one shows in the other.

  1. New store name — the name of the new store. A / becomes -; temp is reserved.
  2. Description — a short note about it. It is shown as a hint when you pick a store in SQL Reports.
  3. Add store — creates the store. It appears in both panels and in every store picker.
  4. Delete store — deletes the store with all its models and databases, after you confirm. main cannot be deleted.
  5. Description of an existing store — edit it here.

Panel

Import Manager

One section per kind of file. Open a section, pick the file, set the options, press Import. The options only appear once a file is picked; Cancel forgets the picked file.

SectionFor
Import RVMPlant models from AVEVA PDMS / E3D (.rvm). One or several files at once.
Import IFCBuilding and infrastructure models (.ifc). One file at a time.
Import STEPMechanical CAD parts and assemblies (.step, .stp). One file at a time.
Import standard GLBglTF binary files from any 3D program (.glb). One file at a time.
Import merged glbGLB files made by the rvm2glb tool in its "merged" mode. A whole folder at once.
Import TDPTreDeSpace's own files (.tdp), for example exported from this app. No conversion, so this is the fastest.

There is no box for importing from a web address. A website that embeds the viewer can import files from its own server; see the API docs.

Options in every section

  • Temp import (don’t keep in store) (ALT 1201) — load the model now but don't keep it: it is removed the next time the app starts.
  • Load after import (ALT 638) — show the result in the 3D view as soon as the import is done. Always on for temp imports.
  • Keep camera (ALT 623) — don't move the camera to the new models.
  • Store — where a kept import goes. Import stays greyed out until you pick one (or tick Temp import).
  • Folder — the folder in the store. It is filled in from the file name; clear it for no folder.

These choices, and the format options below, go back to their defaults every time you start the app — check them before a big import.

Import RVM

The numbers refer to the picture in the walkthrough above.

  1. Select RVM file(s)… (ALT 1000) — pick one or more files. The name, or the number of files, is shown next to it.
  2. Temp import — see Options in every section.
  3. Load after import — the same.
  4. Keep camera — the same.
  5. Store — the store a kept import goes into.
  6. Folder — with one file, the folder name (the file name by default). With several, each file gets its own folder named after it, and the box is greyed out.
  7. Split — one model per SITE (default), ZONE or EQUIPMENT. Smaller pieces can be loaded and unloaded one by one; with ZONE or EQUIPMENT they are put in sub-folders that follow the plant's own structure.
  8. Tolerance — how closely curved surfaces are followed. Smaller = smoother pipes and vessels, but more triangles and a heavier model. Default 0.010.
  9. Include lines — also import line elements, drawn as small crosses. Off by default: there are many and they add clutter. Ticked, a Line width box appears.
  10. Align elements — round the number of segments around circles to a multiple of 4, which gives cleaner shading.
  11. Import (ALT 1001) — start. Converter warnings are listed in the Console.
  12. Cancel — forget the picked files.

Import IFC

  1. Split — one model for the whole file (default), or one per Site, Building or Storey.
  2. Quality — how smooth curved shapes are, from Lowest to Highest (default Medium). Higher = more triangles.
  3. Spaces — the room volumes in the file: Skip (default), Include them with the rest, or put them in a Separate model.
  4. Openings — the cut-outs for doors and windows: Skip, Include or Separate, the same way.
  5. Recenter — move the model to around the origin (on by default).

Import STEP

  1. Deflection — how far a flat triangle may lie from the true curved surface, in mm (default 1.0). Smaller = smoother, more triangles.
  2. Max angle — the largest bend between two segments of a curve, in degrees (default 25). Smaller = smoother.
  3. Workers — how many helpers share the work (0–5, default 2). More is faster but uses more memory.
  4. Cleanup (weld positions) — joins duplicate corner points (on by default). Matches how the app shades models.

The STEP reader is new and may misread some parts. For a file of 200 MB or more the section warns you: the import can need several GB of memory and may crash the tab. Save your work first, and use fewer Workers.

Import standard GLB

  1. Import normals — keep the file's smooth shading (on by default). Off gives flat shading with all the edge lines.
  2. Edge lines — draw edge lines on this model. Turn off for shapes where the lines would clutter the surface. Remembered for this model.

Textures, animation and compressed GLB files (Draco, meshopt) are not supported: such files come in as plain coloured shapes, or are skipped.

Import merged glb and Import TDP

  1. Select folder… (merged glb) — pick a folder. Its sub-folders are searched too; tick the files you want in the list that appears. The Folder box defaults to the picked folder's name, and Pool sets how many files are converted at the same time.
  2. Select files… — pick one or more .tdp files. They go into a folder called misc unless you change it.
  3. Select folder… (TDP) — the .tdp files in one folder, not its sub-folders.
  4. Folder + subfolders… — every .tdp file below a folder. The sub-folders are kept as folders in the library.

With a folder picked, the list starts with nothing ticked: use Select all, or click, Ctrl + click and Shift + click. Import (n) shows how many files will be imported.

Panel

SQL Assets

Your SQLite databases, in the same stores as your models. Like the models, they are stored in this browser on this computer.

  1. Store Config — the same as in Model Assets (see above).
  2. Import to — the store that Import Database copies into. It goes back to main whenever the panel is opened again.
  3. Import Database (ALT 633) — copy one or more SQLite files (.db, .sqlite, .sqlite3, .db3) into that store.
  4. Delete Selected (ALT 634) — delete the selected databases, after you confirm.
  5. Select all / Deselect all — the selection count is shown on the left.
  6. Collapse all / Expand all — fold or unfold every store.
  7. The list — a band per store, with its databases and their size. Click, Ctrl + click and Shift + click to select.

A database that is in use — by a query that is running, or by the app in another tab — is skipped when you import over it or delete it; the Console says so. The line under the list gives the path to use when you attach a database in the SQL Editor: sql_assets/<store>/<file>.

Panel

Export

Writes out what is visible in the 3D view, with its current colours, opacity and moves. Hidden items are left out, so hide or isolate first to export part of a model. Items are always exported in full detail. Your choices here are remembered.

TDP, GLB and IFC

  1. Exclude clipped parts — leave out items that the clipping planes, box or shapes hide completely. An item the clipping cuts through is exported whole. One setting, shown in all three sections.
  2. Export merged TDP (per color) — choose a folder; each loaded model is written there as one .tdp file, in sub-folders like the ones it was loaded from. Smallest and quickest to load.
  3. Export hierarchy TDP — the same, but each item keeps its name and place in the tree. Both TDP exports keep the real coordinates, so a re-import lands exactly on top of the original. A model with nothing visible is left out.
  4. Recenter on bounding box (GLB only, on by default) — move the model to the origin. Plant coordinates far from the origin confuse some programs, PowerPoint for one.
  5. Keep Z up (GLB only) — keep this app's "Z is up". Off, the file uses the usual glTF "Y is up".
  6. Export merged GLB (per color) — one downloaded file, one piece per colour. Small and quick in any viewer.
  7. Export hierarchy GLB — one downloaded file with every item as a named part. Bigger and slower, but keeps the structure.
  8. Export merged IFC — an IFC4 file for BIM tools, one object per colour, at the real coordinates.
  9. Export hierarchy IFC — an IFC4 file with the app's tree as nested, named objects. Bigger.

GLB and IFC are meant for small selections. A whole plant gives a file most programs cannot open; use TDP for full scenes. Labels and measurements are not exported.

State snapshot

Saves the colours, opacity, hidden items and moves — not the models themselves — to one small .tdsnap file. Load it later onto the same models to get the same look back. Items are matched by their name, folder and file, so it keeps working after a reload or a re-import.

  1. Only modified items — save only items you changed (on by default). Off records every item, which makes a bigger file that can repaint another copy of the data completely.
  2. Save colors & visibility — include colour, opacity and hidden items.
  3. Save transforms — include moved, rotated and scaled items.
  4. Skip white (#ffffff) — leave plain white out. It is the unpainted default, so the file gets much smaller.
  5. Skip hidden state — don't record what is hidden, so loading the file never hides anything.
  6. Store — save only the models from one store, or All stores.
  7. Save snapshot — writes the file and downloads it.
  8. Load colors & visibility — apply the file's colours, opacity and hidden items.
  9. Load transforms — apply the file's moves.
  10. Skip white (#ffffff) — ignore plain white in the file; those items keep their own colour.
  11. Skip hidden state — ignore the file's hidden items; only colours and opacity are applied.
  12. Store — apply only to the models of one store. This also lets a snapshot saved from one plant be applied to another with the same structure.
  13. Load snapshot… — pick a .tdsnap file and apply it.

Loading a snapshot replaces the current colours (and/or moves) and clears their undo history — you are asked first. Models in the file that are not loaded are skipped, and a message lists them.
