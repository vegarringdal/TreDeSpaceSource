## 3. Import / export performance

Scope: `src/lib/cooker/**`, `src/lib/model/**`, `src/lib/opfs/**`, `src/lib/modeldb/**`,
`src/lib/{rvm2glb,ifc2glb,step2glb}/**`, `src/components/panels/{import-manager,export}/**`,
`src/state/assets/**`, `src/state/viewer/residency.*`, `src/lib/{zip,xlsx,md5}.ts`,
`rust_src/crates/{cooker-core,cooker-wasm,rvm-*,ifc-*,step-*}`.

**Status (2026-09-12):** 3.1–3.4 landed (CHANGELOG 2026.09.12, >0.0.116). 3.1 hashes in the cooker
worker for every source kind and also covers converter-fed `.tdp` batches (the no-worker bypass is
gone). 3.3 went the wasm route: `ExportNode` tree → flat merged model (`mergedFlat.ts`) →
`cookMergedModel`; ids keep the generic cook's sequential scheme — preserving source ids in an export is
a possible follow-up. 3.4 is `cook_model_both` (golden test pins byte parity with two separate cooks);
STEP untouched. Verified headless: RVM / merged GLB / IFC import, tdp + GLB export in both modes,
re-import of the exports with matching bounds, item counts and worker-side MD5s.


**Status (2026-09-13):** 3.6, 3.7, 3.9–3.16 landed (CHANGELOG 2026.09.13,
>0.0.118) — section 3 is now empty. See `REVIEW_20260912_DONE.md` § 3 for each
finding and what it became. The two deliberately-partial ones are recorded
there: 3.9 does NOT flush each model to the output file as it is added (the GLB
container writes its JSON chunk before the binary one, so the node tree must be
complete first — a container rewrite, not a streaming tweak), and 3.10 does NOT
stage the IFC input to OPFS for range reads (the review's own "longer term"
half; the mesh clones it quantified are gone).

Both Rust changes are byte-parity verified: the cooker against the Huldra RVM
sample (full AND coarse variants) and the IFC front end against every committed
sample in three mode/split combinations, each cooked on both revisions and
compared by digest. All four wasm binaries were rebuilt.

**Nothing open.**

### Done well
- OPFS writes happen in workers via sync access handles with a staging buffer and no per-chunk flush;
  cooker / modeldb write outputs directly, only sizes cross to the main thread.
- GLB export streams typed-array views straight to the sink; IFC export streams text in large flushes.
- Every large buffer crosses Comlink with `transfer`; downloads use `URL.createObjectURL(file)` on the OPFS
  `File`, no JS copy.
- STEP: range reads behind a page cache, index streamed once and shared read-only, per-worker spill / cache
  files, coarse from `coarsen_full` not a model clone.
- RVM: streamed input through a sync handle, outputs handed to a writer sub-worker while wasm blocks.
- Cooker pool workers are terminated after each batch (`cookerPool.ts:44`); merged-GLB batches overlap
  download and cook per slot.
- `format.ts` decodes each meshopt stream into an exactly sized buffer; `compute_dense_bounds` uses
  `select_nth_unstable`; hierarchy CSR is a counting sort.
- `Md5` is incremental and already used for streamed SQL imports; snapshot apply reads by `file.slice()` ranges.

## 4. Rendering

Scope: `src/lib/render/**` and `src/components/panels/viewport/**`.
Default config that matters for weighting: `msaa4x: true`, `geoEdges` / `itemEdges: true`,
`fastAA: false`, `aoMode: 0`, `transparencyBlend: true`, `selectionStyle: 'tint'`, `fpsLimit: 30`.
Note for any shader edit: `tests/shaders.pin.test.ts` pins the WGSL text; regenerate snapshots.


**Nothing open.** Every section-4 finding is closed — 4.1, 4.4 and 4.6 fixed, 4.2
and 4.5 declined, and the whole LOW tail (4.3, 4.7-4.18) declined as a batch on
2026-09-13. All of them, with their diagnoses and the re-open conditions, are in
`REVIEW_20260912_DONE.md` § 4.

### Done well
- Idle skip is real: converge-then-idle, and a hold path that re-presents the TAA sum for overlay-only frames
  (hover / pulse / picks) so nothing scene-side is encoded; burst hold for residency.
- No stalls in the loop: every readback is a 1-texel / 64-B copy behind an in-flight guard (`pickInFlight`,
  `itemPick.inFlight`, `snapInFlight`, `statsInFlight`, timings `inFlight`); no awaited `mapAsync`, no
  `onSubmittedWorkDone`; draw-count stats throttled to 2 Hz + first still frame.
- Draw counts live in one buffer at 256-B slots (single `clearBuffer`, single stats copy); two-pass cull with
  HZB built from the MSAA depth as a min over all samples (conservative); revived slots seed `vis = 0`.
- Target lifecycle is clean: every texture is destroyed before recreation; AO / history textures collapse to
  1×1 when their pass is off; all resources labelled; `allocationTracker` keeps VRAM honest.
- Frame uniform layout is centralised (`frameLayout.ts`) with dynamic-offset slots so one bind group per
  model serves every pass; keyed uploads for clip / lines / markers / item states (only on change).
- Reverse-Z `depth32float` with infinite far + camera-relative rebase; TAA jitter applied after the change
  check so it never reads as motion; selection / state changes reset the history (no ghosting).

## 5. Transparency / blend ordering

Scope: `renderer.ts` blend pass and pipelines, `shaders/{cull,scene,post}.ts`,
`frameLayout.ts`, `state/viewer`, `modeldb/{apiColor,colorRules}.ts`.

### Current state

The sorted blend pass landed (DESIGN.md → "Sorted blend pass"): a dedicated
depth-bucketed transparent list out of the cull, drawn back-to-front with a
winding-free front/back split, in place of the full-scene replay. The option
survey behind it, the pre-rewrite state and the four artifacts it fixed are in
`REVIEW_20260912_DONE.md` § 5.

Premultiplied vs straight alpha is consistent (straight on both sides); blending happens on the raw scene
format with no `-srgb` view, matching the no-conversion rule. No bug there.

**Ruling (2026-09-15):** section 5 is closed. The LOW tail (5a.5, 5a.6, 5c.1)
is declined as a batch on the section-4 grounds — each is a known consequence of
where the blend pass sits in the frame, and two of the three argue against
themselves (5a.5 is native parity, 5c.1 would cost per-sample shading). 5a.7
(cross-model ordering) and 5a.8 (the blend pass has no adaptive fallback when
transparency is the whole scene, measured at 44 of 50 ms on a 136-model scene)
are both **DECLINED** as too expensive for what they buy — and 5a.8's two levers
cost nothing: the MDI path (Chrome's multi-draw flags) drops the vertex-pull
fallback's flat 372-vertex draws, and `transparencyBlend: false` is the right
mode for a wholesale-ghosted scene.

**Nothing open.** Every diagnosis, the measurement behind the two rulings and
each re-open condition are in `REVIEW_20260912_DONE.md` § 5.

## 6. Client (postMessage) API

Scope: `api/tredespace-client.ts`, `EVENTS.md`, `src/lib/messageApi/**`,
`src/state/apiSecurity.*`, `src/state/externalApp*`, `src/state/externalPanels/**`,
`scripts/gen-api-docs.mjs`, `tests/`.


**Status (2026-09-13):** 6.4, 6.5, 6.10–6.14 landed (CHANGELOG 2026.09.13,
>0.0.118) — see `REVIEW_20260912_DONE.md` § 6. The protocol gained three
things a host can see: commands from one client now run in ARRIVAL ORDER
(`parallel: true` opts one out), a `command.cancel` note stops an in-flight
command (and the SDK's timeout sends it), and two new error codes — `download`
and `sql` — carry caller errors that used to arrive as `internal`. Both are in
EVENTS.md and in the SDK's union.

Partial by nature, and recorded there: cancellation cannot stop work already
inside the SQLite worker or a synchronous wasm call (killing the worker would
abort every tab's query), so those answer `cancelled` without stopping early.

**Ruling (2026-09-15):** the command surface is deliberately not exhaustive.
The API is there to drive a viewer a host embeds, not to replace the person
sitting in front of it. 6.9 (the state-layer capabilities with no wire
representation) is closed as **BY DESIGN** in `REVIEW_20260912_DONE.md` § 6 —
commands and events get added when a host actually needs one, not to close a
symmetry gap. 6.15 (`fetch` credentials on the `*Url` commands) is closed the
same way: the viewer is meant to be self-hosted, and same-origin cookies riding
along is the point, not a leak.

**Nothing open.** Both rulings, with the original diagnoses and their re-open
conditions, are in `REVIEW_20260912_DONE.md` § 6.

### Done well
- Correlation ids with a random per-instance prefix; exactly one reply per request; every handler failure
  funnels to `{ code, message }` (`ApiError` or `internal`) and nothing escapes the listener.
- Live per-message origin allowlist; replies go to `event.source` with `event.origin`; `?apiOrigins=` in
  an opened window requires user consent and `*` is never granted that way.
- Ready race handled: `client.hello` → `announceReadyTo`, and there is no `await` between listener install
  and `markApiReady`; `app.bye` / bfcache handled on both sides.
- Bus identities are app-assigned and origin-stamped; targeted delivery posts once with the exact origin.
- Zero-copy `bytes` side-channel, chunked upload for large files, packed name lists, SQL results that never
  cross the boundary for colour / select.
- Strict settings validation with compile-time SDK parity; unknown keys rejected.
- No injection path found: `richTextHtml` escapes before `innerHTML` (`richText.ts:4,19`); dialog text
  renders through React; structured clone + allowlisted spreads rule out prototype pollution.
- Build-enforced JSDoc + EVENTS example; `Result<T>` never-throw SDK; `AbortSignal` on subscriptions;
  relay requires a concrete origin.
